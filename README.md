# wg-admin-bash

Интерактивные скрипты администрирования WireGuard-сервера (топология
**Hub-and-Spoke**) с текстовым меню. Один сервер-хаб объединяет удалённые
компьютеры в единую VPN-сеть.

Проект поставляется двумя равноценными портами:

| Скрипт | Платформа | Требования |
|---|---|---|
| [`wg-admin.sh`](wg-admin.sh) | Debian 11/12, Ubuntu 20.04/22.04/24.04 (x86_64, arm64) | root, bash ≥ 4.4 |
| [`wg-admin.ps1`](wg-admin.ps1) | Windows 10/11, Server 2016+ (x64/arm64) | PowerShell 5.1+, Администратор |

Оба скрипта самодостаточны: один файл, без внешних зависимостей сверх
штатных пакетов ОС и самого WireGuard.

## Возможности

- **Установка WireGuard** из интерфейса (Linux — `apt`, Windows — официальный
  установщик).
- **Инициализация сервера**: ключи, конфиг, NAT, проброс порта, IP-форвардинг,
  автозапуск сервиса — за один проход.
- **Управление клиентами**: добавление с интерактивным диалогом (12 шагов с
  дефолтами), список с фильтрами и экспортом CSV, редактирование, удаление
  (одного / нескольких / всех неактивных), отключение без удаления.
- **Срок действия клиентов**: `30d`, `12h`, `never`, `YYYY-MM-DD`. Истёкшие
  автоматически отключаются (не удаляются), продление включает обратно.
- **Мониторинг**: `wg show` с классификацией пиров (активные / молчащие /
  потерянные), трафик rx/tx по клиентам, ping, публичный ключ, внешний IP.
- **Сервис**: старт/стоп/рестарт, автозапуск, перезагрузка конфига **без
  разрыва активных сессий** (`wg syncconf`).
- **Маршрутизация**: доступ к LAN сервера, LAN за клиентом, site-to-site,
  split-tunnel, DNS, ограничение скорости.
- **Безопасность**: Firewall, ограничение по IP, аудит подключений, ротация
  ключей сервера.
- **Бэкап**: конфиги / конфиги+сроки / полный, восстановление, автобэкап по
  расписанию.
- **Обслуживание и диагностика**: очистка неактивных, удаление истёкших,
  проверка форвардинга/NAT/порта/DNS, отчёт для поддержки.
- **Интерфейс**: русский и английский (переключается в настройках), цветной
  вывод, уровень логирования.

## Как это работает

### Топология

```
        [Интернет]
             |
     ┌───────┴────────┐
     │  WireGuard     │  ← сервер-хаб (этот скрипт)
     │  10.8.0.1      │
     └──┬─────┬───┬───┘
        │     │   │
     pc1    pc2  pc3     ← споки (клиенты)
   10.8.0.2 .3   .4
```

Сервер слушает UDP-порт (по умолчанию **51820**), маршрутизирует трафик между
клиентами и наружу через NAT. Клиенты видят друг друга по VPN-адресам.

### Формат конфигурации

Используется стандартный формат WireGuard. Управление клиентами ведётся
через именованные блоки пиров в конфиге сервера:

```ini
# pc1
# COMMENT рабочий ноутбук
[Peer]
PublicKey = ...
AllowedIPs = 10.8.0.2/32
PersistentKeepalive = 25
# EXPIRES 1893456000
```

Служебные комментарии скрипта:

| Маркер | Значение |
|---|---|
| `# <имя>` | начало блока клиента (имя: буквы, цифры, `_`, `-`) |
| `# COMMENT <текст>` | описание клиента |
| `# EXPIRES <unix_ts>` | срок действия (0 или отсутствие = бессрочно) |
| `# DISABLED 1` | клиент отключён (строки `[Peer]` закомментированы) |

Эти же маркеры используются обоими портами — конфиги переносимы.

### Применение без разрыва

Любое изменение конфига применяется через:

```bash
wg syncconf wg0 <(wg-quick strip wg0)      # Linux
wg.exe syncconf wg0 <stripped-config>      # Windows
```

Активные сессии клиентов **не рвутся**. Полный перезапуск туннеля нужен только
при смене порта/ключей сервера.

## Установка и первый запуск

### Linux (Debian / Ubuntu)

```bash
# 1. зависимости
sudo apt update
sudo apt install wireguard wireguard-tools qrencode iptables

# 2. запуск скрипта
sudo bash wg-admin.sh
```

### Windows

1. Скачайте WireGuard для Windows с [wireguard.com/install](https://www.wireguard.com/install/)
   или используйте пункт меню **[1] Установка WireGuard** (скачает официальный
   установщик и запустит его в тихом режиме).
2. Откройте PowerShell **от имени Администратора**:

```powershell
cd C:\путь\к\скрипту
powershell -ExecutionPolicy Bypass -File wg-admin.ps1
```

> `ExecutionPolicy Bypass` нужен однократно для запуска неподписанного скрипта.
> Альтернатива: `Unblock-File wg-admin.ps1` затем обычный запуск.

### Сценарий первого запуска

После старта появится главное меню:

```
  1)  Установка WireGuard
  2)  Инициализация сервера
  3)  Управление клиентами
  ...
  0)  Выход
```

**Шаг 1. Проверьте компоненты** — пункт `[1]` → `Проверить установленные
компоненты`. `wg`, `wireguard` должны быть найдены.

**Шаг 2. Инициализация сервера** — пункт `[2]`. Скрипт спросит (в скобках —
значение по умолчанию, достаточно Enter):

| Вопрос | По умолчанию | Пояснение |
|---|---|---|
| Внешний интерфейс | авто (`eth0` / `Ethernet`) | интерфейс с выходом в интернет |
| VPN-подсеть | `10.8.0.0/24` | адресное пространство VPN |
| VPN IP сервера | `10.8.0.1` | адрес хаба внутри VPN |
| Порт UDP | `51820` | порт WireGuard |
| DNS | `1.1.1.1` | DNS для клиентов |
| MTU | пусто (авто) | задавайте только при проблемах |

Далее автоматически:

1. Генерируются ключи сервера (приватный — с правами только для администратора).
2. Создаётся конфиг сервера с NAT и пробросом в `PostUp`/`PreDown`.
3. Включается IP-форвардинг.
4. Настраивается NAT и Firewall.
5. Туннель запускается и ставится в автозапуск.

В конце выводится **публичный ключ сервера** и внешний адрес — они нужны для
клиентских конфигов.

**Шаг 3. Добавьте клиентов** — пункт `[3]` → `Добавить клиента` (подробнее
ниже).

## Полное руководство по меню

### [1] Установка WireGuard

- **Установить компоненты** — Linux: `apt install wireguard wireguard-tools
  qrencode iptables`; Windows: скачивание и тихая установка официального
  установщика.
- **Проверить установленные компоненты** — статус `wg`, `wireguard`,
  туннель-сервисов.
- **Обновить WireGuard** — Linux: `apt upgrade`; Windows: переустановка
  последней версии.

### [2] Инициализация сервера

Описана выше. Повторный запуск спрашивает подтверждение перезаписи и создаёт
бэкап старого конфига.

### [3] Управление клиентами

| Пункт | Действие |
|---|---|
| 3.1 | Добавить клиента (диалог из 12 шагов) |
| 3.2 | Список клиентов (фильтры: все / активные / отключённые / истёкшие, экспорт CSV) |
| 3.3 | Редактировать клиента (IP, ключ, keepalive, срок, комментарий, перегенерация ключей) |
| 3.4 | Удалить клиента (одного / нескольких / всех неактивных) |
| 3.5 | Отключить / включить клиента |
| 3.6 | Управление сроком действия |
| 3.7 | Показать конфиг клиента (в терминале / QR / сохранить в файл) |

### [4] Мониторинг и статистика

- **wg show** — полный вывод + сводка: активные (был handshake < 5 мин),
  молчащие (5–30 мин), потерянные (> 30 мин).
- **Трафик по клиентам** — rx/tx, сортировка по имени/приёму/отправке, экспорт
  CSV, сброс счётчиков.
- **Состояние сервиса** — статус службы и интерфейса.
- **Ping всех пиров** — проверка доступности по VPN-адресам.
- **Публичный ключ сервера** / **Внешний IP** — данные для клиентов.

### [5] Управление сервисом

- Запустить / Остановить / Перезапустить туннель.
- Включить / отключить автозапуск.
- **Перезагрузить конфиг без разрыва** — `wg syncconf`, сессии сохраняются.
- Журнал работы.

### [6] Редактирование конфигурации

- Открыть конфиг в редакторе (`nano` / Блокнот) с последующей проверкой
  синтаксиса и применением.
- Проверка синтаксиса (секции, ключи, дубликаты `AllowedIPs`).
- Смена внешнего интерфейса, порта, VPN-подсети.

### [7] Маршрутизация

- **Доступ клиентов к LAN сервера** — разрешает заход из VPN в локальную сеть
  сервера. Дополнительно добавьте LAN-подсеть в `AllowedIPs` клиента.
- **Доступ к LAN за клиентом** — прописывает подсети удалённого офиса в
  `AllowedIPs` пира (для филиалов).
- **Site-to-Site** — соединение двух сетей через два узла (нужен ключ и endpoint
  удалённой стороны).
- **DNS** — DNS для клиентских конфигов; на Linux можно поставить dnsmasq /
  AdGuard Home прямо на хаб.
- **Ограничение скорости** — Linux: `tc`; Windows: подсказка `New-NetQosPolicy`.
- **Split-tunnel** — через VPN идут только указанные подсети, остальное напрямую.

### [8] Безопасность

- **Firewall** — Linux: `ufw` или `iptables`; Windows: правила `New-NetFirewallRule`.
- **Ограничение по IP** — разрешить подключение к порту WireGuard только с
  указанных адресов.
- **Аудит подключений** — последние действия из лога и история handshake.
- **Ротация ключей сервера** — генерирует новые ключи и обновляет конфиги
  клиентов; рассылку новых конфигов нужно сделать вручную.

### [9] Бэкап / Восстановление

См. раздел [Бэкап](#бэкап-и-восстановление).

### [10] Обслуживание

- **Очистить неактивных** — клиенты без handshake более N дней: показать /
  отключить / удалить.
- **Удалить истёкших** — по срокам действия.
- **Сбросить счётчики трафика** — пересоздание туннеля (краткий разрыв).
- **Перезагрузка** — сервера (Linux) или компьютера (Windows).
- **Диагностика** — переход в меню [11].

### [11] Диагностика

| Проверка | Что делает |
|---|---|
| IP-форвардинг | `sysctl` / реестр `IPEnableRouter` |
| NAT | наличие MASQUERADE / `Get-NetNat` |
| Порт извне | показывает `ip:port`, слушатели UDP, команду внешней проверки |
| Ping всех пиров | ICMP по VPN-адресам |
| DNS | запрос `example.com` через указанный DNS |
| Отчёт для поддержки | файл с ОС, конфигом (приватные ключи скрыты), Firewall, логом |

### [12] Настройки скрипта

| Параметр | По умолчанию | Где хранится |
|---|---|---|
| VPN-подсеть | `10.8.0.0/24` | `wg-admin.conf` |
| Порт | `51820` | там же |
| DNS | `1.1.1.1` | там же |
| Цветной вывод | вкл | там же |
| Уровень логирования | `INFO` (DEBUG/INFO/WARN/ERROR) | там же |
| Язык интерфейса | `ru` (`ru`/`en`) | там же |

Настройки применяются к **новым** операциям и сохраняются автоматически.

### [13] Удаление WireGuard

Пошаговое (остановить сервис → удалить конфиги → очистить NAT/Firewall →
удалить приложение) или полное удаление. Перед удалением конфигов —
подтверждение и бэкап.

### [14] О скрипте

Версия (SemVer), репозиторий, лицензия, проверка обновлений на GitHub.

### [0] Выход

## Работа с клиентами

### Добавление клиента (пункт 3.1)

Интерактивный диалог, Enter принимает значение в скобках:

```
1.  Имя клиента (pc1, laptop-ivan, ...): pc3
2.  VPN IP клиента [10.8.0.3]:
3.  Публичный ключ (пусто = сгенерировать):
4.  Внешний адрес сервера [авто: 203.0.113.5]:
5.  Порт сервера [51820]:
6.  Режим маршрутизации:
      1) Только VPN-сеть (10.8.0.0/24)  ← по умолчанию
      2) Весь трафик через VPN (0.0.0.0/0)
      3) VPN + указанные подсети
      4) Свой вариант (CIDR вручную)
7.  DNS [1.1.1.1]:
8.  PersistentKeepalive [25]:
9.  MTU (пусто = авто):
10. Срок действия (30d / 12h / never / YYYY-MM-DD) [never]:
11. Комментарий (описание):
12. Показать QR-код? (y/N):
```

**Результат:**

- Файл клиента: Linux `/etc/wireguard/clients/<имя>.conf`,
  Windows `C:\ProgramData\wg-admin\clients\<имя>.conf` (права — только
  администратор).
- Блок `[Peer]` добавлен в конфиг сервера.
- Если задан срок — маркер `# EXPIRES` и запись в `expiry.db`.
- Конфиг применён без разрыва сессий.

### Режимы маршрутизации

| Режим | AllowedIPs клиента | Когда использовать |
|---|---|---|
| Только VPN-сеть | `10.8.0.0/24` | доступ к ресурсам VPN, интернет — напрямую |
| Весь трафик | `0.0.0.0/0` | полный туннель (анонимность, обход блокировок) |
| VPN + подсети | `10.8.0.0/24, 192.168.10.0/24` | доступ к VPN и к конкретным офисным сетям |
| Свой CIDR | вручную | нетиповые схемы |

### Передача конфига клиенту

1. **Файл** — скопируйте `.conf` на устройство (USB, scp, курьер).
2. **QR-код** — отсканируйте в мобильном приложении WireGuard (пункт 3.7).
3. **Импорт** — в приложении WireGuard: «Импорт из файла».

Для Android/iOS удобнее QR; для Windows/Linux — файл.

### Отключение vs удаление

**Отключение** (пункт 3.5) — безопасно: пир закомментирован, из `wg show`
пропал, но конфиг и статистика сохранены. Продление срока или повторное
включение мгновенно возвращает клиента.

**Удаление** (пункт 3.4) — стирает пир и файл конфига безвозвратно.

## Срок действия и автоблокировка

### Форматы срока

| Ввод | Результат |
|---|---|
| `never` | бессрочно |
| `30d` | 30 дней с момента установки |
| `12h` | 12 часов |
| `2026-12-31` | до конца этого дня (23:59:59) |
| `1735689600` | конкретный unix-timestamp |

### Что происходит при истечении

По умолчанию клиент **отключается, но не удаляется**:

1. Строки `[Peer]` в конфиге сервера закомментированы.
2. Добавлен маркер `# DISABLED 1`.
3. Пир исчезает из `wg show` — трафик не идёт.
4. Файл конфига клиента остаётся на месте.

**Продление срока** автоматически раскомментирует строки и убирает маркер.

### Автопроверка (пункт 3.6 → 5)

| ОС | Механизм |
|---|---|
| Linux | cron `*/5 * * * * /usr/local/bin/wg-expire-check.sh` **или** systemd-timer |
| Windows | задача Планировщика `wg-admin-expire-check` каждые 5 минут |

Скрипт проверки читает `expiry.db`, отключает истёкших и применяет конфиг
без разрыва. Проверку можно отключить в том же пункте.

## Файлы и расположение

### Linux

```
/etc/wireguard/
├── wg0.conf              # конфиг сервера
├── server_private.key    # приватный ключ (600, только root)
├── server_public.key     # публичный ключ
├── clients/
│   ├── pc1.conf          # конфиг клиента (600)
│   └── ...
├── expiry.db             # база сроков (имя:unix_ts)
└── wg-admin.conf         # настройки скрипта
/var/log/wg-admin.log     # журнал действий
/usr/local/bin/wg-expire-check.sh   # скрипт автопроверки (если включена)
```

### Windows

```
C:\ProgramData\wg-admin\
├── server.conf
├── server_private.key    # icacls: Administrators + SYSTEM
├── server_public.key
├── clients\*.conf
├── expiry.db
├── wg-admin.conf
├── logs\wg-admin.log
├── backups\*.zip
└── wg-expire-check.ps1   # скрипт автопроверки (если включена)
```

### Журнал

Формат: `[YYYY-MM-DD HH:MM:SS] [LEVEL] сообщение`

Уровни: `DEBUG`, `INFO`, `WARN`, `ERROR`. Уровень переключается в меню [12].
Все мутирующие действия (добавление клиента, смена порта, удаление) пишутся в
журнал — удобно для аудита.

## Бэкап и восстановление

### Создание (пункт 9.1)

| Режим | Содержимое |
|---|---|
| Только конфиги | `server.conf` + `clients/` |
| Конфиги + база сроков | + `expiry.db` |
| Полный | + ключи, настройки, журнал |

Архивы: Linux `tar.gz` в `/var/backups/wg-admin/`, Windows `zip` в
`C:\ProgramData\wg-admin\backups\`. Права — только администратор.

### Восстановление (пункт 9.2)

1. Перед распаковкой автоматически создаётся бэкап текущего состояния
   (`pre-restore-*`) — можно откатиться.
2. Файлы распаковываются поверх.
3. Предлагается применить конфиг.

### Автобэкап (пункт 9.3)

| ОС | Расписание |
|---|---|
| Linux | cron: ежедневно в 03:17 или еженедельно (воскресенье 03:17) |
| Windows | Планировщик задач: ежедневно / еженедельно |

Автобэкап хранит последние 30 архивов (Linux), старые удаляются.

### Рекомендации

- Бэкап после каждого добавления/удаления клиентов и перед ротацией ключей.
- **Приватные ключи в архиве** — храните его как секрет (полный режим).
- Проверяйте восстановление на тестовом стенде, а не в проде.

## Диагностика проблем

| Симптом | Проверка | Решение |
|---|---|---|
| Клиент не подключается | `wg show`: есть ли handshake? | Проверьте порт, Firewall, правильность endpoint |
| Handshake есть, трафика нет | Меню [11] → NAT, форвардинг | Включите IP-форвардинг, пересоздайте NAT |
| Пинг VPN-адресов не проходит | `AllowedIPs` клиента содержит VPN-подсеть? | Исправьте режим маршрутизации |
| Сессии рвутся при изменениях | Используете `systemctl restart`? | Применяйте «Перезагрузка конфига без разрыва» |
| Порт не виден снаружи | Меню [11] → Проверить порт извне | Проброс UDP на роутере, Firewall |
| `Permission denied` на ключах | Права файлов | Linux: `600`, владелец root; Windows: только Administrators |
| Скрипт не запускается на Windows | ExecutionPolicy | `powershell -ExecutionPolicy Bypass -File wg-admin.ps1` |
| Русский текст — кракозябры (Windows) | UTF-8 BOM в `.ps1` | Пересохраните файл с BOM (см. `AGENTS.md`) |

### Команды для быстрой проверки

## Частые вопросы

**Сколько клиентов поддерживается?**
Ограничение — размер VPN-подсети. Для `/24` это ~250 клиентов; подсеть
настраивается. Жёсткого лимита в скрипте нет.

**Можно ли управлять несколькими серверами?**
Каждый экземпляр скрипта управляет одним туннелем. Для нескольких серверов —
несколько копий с разными каталогами конфигурации.

**Как сменить порт?**
Меню `[6]` → `Изменить порт` (обновит конфиг, Firewall, применит без разрыва).
На роутере потребуется новый проброс.

**Как добавить сеть за клиентом (филиал)?**
Меню `[7]` → `Доступ к LAN за клиентом`, затем добавьте эту подсеть в
`AllowedIPs` устройств, которые должны ходить в филиал.

**Ключи скомпрометированы — что делать?**
Меню `[8]` → `Ротация ключей сервера`, затем раздайте клиентам новые конфиги
(пункт 3.7).

**Меняется ли IP клиента при продлении срока?**
Нет. Срок влияет только на включение/отключение пира.
